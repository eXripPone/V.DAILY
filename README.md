## Быстрый локальный запуск

Python 3.11 или новее. Для демо не нужны пакеты, API-ключи, Docker или Node.js.

```powershell
cd vdaily_mvp
python -m app.server --demo
```

Откройте http://127.0.0.1:8080. На Windows можно запустить `start_demo.ps1`; он также умеет использовать Python, поставляемый с Codex. Сервер работает до Ctrl+C. Если порт занят: `--port 8081`. Собственная база: `--db demo.sqlite3`.

Выберите свой часовой пояс, затем введите:

> Завтра в 15:00 встреча с Андреем, на обед борщ, не забыть оплатить интернет, потратил 550 на такси

Измените расход на 500, подтвердите набор. В «Сегодня» видны три записи; встреча доступна в календаре на завтра и в «Истории». Без подтверждения ни одной сохранённой записи не появляется. Отдельно попробуйте «Потратил на такси» и «Завтра в три встреча»: потребуется уточнение суммы или времени.

Деморежим использует ограниченный локальный разбор по правилам. Это способ проверить продуктовый поток, а не измерение качества нейросети. Он доступен только на localhost, не принимает авторизацию произвольного Telegram-пользователя и явно обозначен в интерфейсе.

Консольное демо: `python demo.py`.

## Рабочий Telegram-бот и Mini App

1. Создайте бота в BotFather и получите токен.
2. Подготовьте ключ Anthropic и выберите доступную в вашем аккаунте модель.
3. Для голоса установите FFmpeg, затем `python -m pip install -r requirements-live.txt`. Whisper при первом использовании скачивает модель `base`; для предсказуемого времени прогрейте её до пилота.
4. Подключите HTTPS-домен и обратный прокси. Пример конфигурации Caddy: `Caddyfile.example`. TLS должен поддерживать не ниже 1.2; приложение слушает только 127.0.0.1. Не открывайте порт 8080 наружу.
5. Установите переменные окружения в том же терминале:

```powershell
$env:TELEGRAM_BOT_TOKEN = 'токен вашего бота'
$env:ANTHROPIC_API_KEY = 'ваш ключ'
$env:ANTHROPIC_MODEL = 'claude-sonnet-4-6'
$env:VDAILY_PUBLIC_URL = 'https://ваш-домен.example'
$env:VDAILY_TRUST_PROXY = '1'
python -m app.server --db vdaily.sqlite3
```

`.env.example` — шаблон значений, он не загружается автоматически. В архиве нет ключей. ID модели настраивается, доступность определяется вашим провайдером.

В BotFather задайте HTTPS-адрес Mini App. После `/start` бот также выдаёт кнопку открытия. Оба транспорта используют один сервис и одну базу. Не запускайте второй экземпляр polling для того же токена.

Без `--demo` нет автоматической демоавторизации. Сервер проверяет подпись Telegram initData и срок auth_date, выдаёт часовой сеанс, изолирует данные по проверенному user_id и отклоняет HTTP-доступ к закрытым данным без доверенного локального HTTPS-прокси. Не включайте trust_proxy для удалённого недоверенного прокси.

## Команды бота

- `/start` — инструкция и Mini App.
- `/tz Europe/Moscow` — выбрать часовой пояс IANA. Перед первым вводом выбор обязателен.
- Текст или голос — новый набор черновиков; лимит текста/расшифровки 1000 символов.
- `/drafts` — неподтверждённые наборы, в том числе после перезапуска.
- Кнопка «Изменить запись N» — затем `amount=500`, `date=2026-12-01`, `time=15:00`, `category=Транспорт` и т. п.
- Для смены раздела отправьте JSON с новым type и его полями, например `{"type":"task","title":"Купить подарок"}`. В Mini App раздел меняется обычной формой.
- `/cancel` — выйти из редактирования; кнопка «Отменить» отменяет конкретный набор.
- `/today`, `/calendar 2026-12-01`, `/finance`, `/history` — чтение сохранённых записей.

Разговоры поддерживаются в личном чате. В группах бот не раскрывает персональные записи. Долгие внешние операции выполняются в рабочих потоках, HTTP-интерфейс остаётся доступным.

## Сохранение и предметные правила

- Каждая карточка связана с постоянным batch_id и revision. Старая версия редактируемого черновика не подтверждается; старая карточка другого набора не сохраняет новый набор.
- Набор сохраняется одной SQLite-транзакцией. При сбое частичных записей нет; черновик остаётся доступным для повторной попытки.
- Повторное подтверждение возвращает уже созданные ID; уникальность действует и после перезапуска.
- Дата события/срок задачи определяют день отображения. Для расходов, еды и заметок используется явно указанная дата либо локальная дата пользователя. Задачи без срока всегда доступны в истории.
- Несуществующие даты, NaN/Infinity/bool вместо суммы, неположительные расходы и валюта не RUB отклоняются. Отсутствующая обязательная информация допускается только в черновике.
- «В три» требует явного времени; «в 15:00» однозначно. Уведомление создаётся только по явной просьбе. Напоминания хранятся в базе, проверяются каждые 5 секунд, имеют блокировку отправки, ограничение повторов и повторную попытку после сбоя. Как у любого внешнего API без идемпотентной отправки, авария строго между доставкой Telegram и фиксацией результата может привести к повтору; абсолютное exactly-once не заявляется.
- КБЖУ: калории и Б/Ж/У, масса порции, явная отметка приблизительности. Для неизвестного блюда без полноценной оценки сохранение требует уточнения. В демо есть небольшой справочник для борща, овсянки, риса и гречки; это ориентиры, не медицинская оценка.

## Проверки и трассировка

```powershell
python -m unittest discover -s tests -v
python tools/verify.py
```

Второй запуск сохраняет фактические результаты в `verification/`. `docs/IMPLEMENTATION_RTM.md` связывает исходные FR/NFR с кодом и проверками. Исходные PRD/SRS/US/RTM не изменены. В `docs/RELEASE_NOTES.md` перечислены устранённые дефекты и границы проверки.

Модульные/интеграционные тесты используют подставные внешние сервисы. Они проверяют сохранение, интерфейс HTTP, обработчики Telegram и безопасность, но не доказывают точность LLM или STT. Работа живых сервисов, 95-й перцентиль времени, 99% доступности за месяц и продуктовые метрики требуют отдельного прогона и пилота.

## Продуктовые метрики

`python -m app.manage metrics --db vdaily.sqlite3`

M-01: активация за 24 часа только для пользователей с полным 24-часовым наблюдением. M-02: семь последовательных 24-часовых интервалов от первого контакта; среднее по пользователям с хотя бы одним сохранением в эти семь суток и завершённым наблюдением. M-03: уникальные предложенные записи, сохранённые без редактирования / все предложенные, включая отменённые. M-04: уникальные подтверждённые записи, отсутствующие после попытки сохранения / все подтверждённые. Повторная успешная попытка устраняет текущую потерю. M-05: доля существенных ошибок в экспертной разметке. При отсутствии нужной выборки — null, а не выдуманный результат.

Аналитика хранит только ID, тип события и UTC-время, без текста личных сообщений. Черновики и записи, естественно, содержат пользовательские данные и должны храниться в защищённой серверной базе. Исходные сообщения не выводятся в журналы ошибок.

Для M-05 локальный оператор размечает CSV с колонками `record_id,major_error` (0 или 1) и импортирует: `python -m app.manage review --db vdaily.sqlite3 --csv reviews.csv`. Административная статистика не открыта обычным пользователям Mini App.

## Эксплуатация

Проверка сервера: `/health` (включает проверку базы). Сбор доступности раз в 5 минут: `python tools/monitor.py https://ваш-домен.example`. Для NFR-04 требуется полный календарный месяц наблюдений; CSV не содержит личных данных. Бэкап делайте SQLite backup API или после штатной остановки, учитывая WAL. Старый файл БД из прототипа автоматически не мигрируется: используйте новую базу для этой версии, старую сохраните отдельно.

Для живого стенда подготовьте 200 русских текстов и 200 аудио до 60 секунд, зафиксируйте модель, конфигурацию сервера и клиента; замерьте NFR-01/02. Отдельно проверьте 200 открытий экрана со 100 записями и согласованной сетью, затем Telegram Android/iOS/Desktop. Пользовательский пилот нужен для M-01–M-05 и гипотезы ускорения; результатов такого пилота в поставке нет.

API-справка: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app и https://platform.claude.com/docs/en/api/messages.
